## Scope and recovery

Charts, private brand presets, private compatibility UI and runtime-dependent
KYC/wallet widgets are excluded. The starter's live sandbox verification still
requires a supported service and provisioned access; fixtures prove the example
behavior, not a live financial integration.

Keep the exact lockfile and archive manifests with each consumer release. For
a bad release, restore the previous verified consumer lockfile and deployment
artifact, run its consumer/browser checks, then publish a new patch version.
Never overwrite release assets or move a release tag. For first adoption with
no known-good UI version, roll back the adopting application release.
